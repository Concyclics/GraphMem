# V5.56 AnswerPlan 实现与消融结论（2026-08-13）

## 结论

V5.56 实现了一个 label-free、确定性的 `AnswerPlan` 编译器，目标是修复
“64-turn 召回已经包含 gold turn，但无思考回答模型仍绑定错事件或日期”的
错误。该实现已经进入核心代码，但默认关闭。原因是双模型配对消融没有通过
no-regression 门禁，因此它不是 V5.54 的正式准确率提升项，也不应写入主结果。

## 实现边界

- 编译器只读取冻结的 question、packed evidence、QuerySlots 和运行 trace；不读取
  gold answer、judge verdict 或 benchmark 标签。
- 它不删除、不替换、不重排 evidence，只在 V5.54 readout 后追加有界的候选绑定。
- duration 问题独立匹配两个 event clause；每个 endpoint 必须有不同的词法 witness，
  并且至少来自两个 source turn。
- temporal-order 只匹配显式的 `who/which ... first/earlier/later/earliest`，不再将
  `last weekend`、`last trip` 等普通时间修饰语误判为排序任务。
- 超过 hard prompt budget 时逐级缩短候选；仍超限则返回原始 prompt。
- 正式 CLI 使用 `--answer-plan` 开启，并用可重复的 `--answer-plan-kind`、
  `--answer-plan-max-candidates`、`--answer-plan-excerpt-chars` 控制；这些字段都会写入
  manifest 和 answer cache identity。

## 实验口径

- 回答模型：Qwen3-30B 与 GPT-5.4-mini，均关闭 reasoning。
- Judge：`gpt-5.6-luna`，固定 prompt/temperature/seed。
- 主诊断集：LME500 中 packed turn-level gold all-hit 的 90 题。
- 全量验证：LongMemEval 500 题。
- 配对统计中，如果新旧 prediction 完全相同，则沿用 baseline verdict，避免同一答案
  被重复 judge 时产生随机翻转。

## 结果

| 版本 | 评测集 | 触发题数 | Qwen3-30B | GPT-5.4-mini | 结论 |
|---|---:|---:|---:|---:|---|
| broad top-3 | all-hit 90 | 44 | 60→53 | 44→43 | 明显回退 |
| broad top-5 | all-hit 90 | 44 | 60→53 | 44→45 | Qwen 明显回退 |
| relational top-4 | all-hit 90 | 22 | 60→62 | 44→44 | 局部看似有效 |
| relational top-4 | LME500 | 124 | 381→373 | 345→343 | 全量回退 |
| operand-aware top-4 | all-hit 90 | 16 | 60→58 | 44→44 | 修正路由后仍未过门禁 |

全量 relational 版本中，Qwen 的逐题转换为 5 gain / 13 loss，GPT-5.4-mini 为
5 gain / 7 loss。修正后的 operand-aware 版本中，Qwen 为 2 gain / 4 loss，
GPT-5.4-mini 为 1 gain / 1 loss。由于最后一版仍降低 Qwen 正确率，没有继续消耗
API 预算跑第二次全量，也没有改变 V5.54 默认配置和报告主表。

## 原因分析

1. 追加原始 evidence excerpt 会重复已经可见的信息，平均额外增加约 600--700
   prompt token，容易改变强模型已经正确的注意力分配。
2. 由问题表面词法重新解析 operands，不能等价替代上游 QueryIR 中已经类型化的
   operator、entity binding 和 temporal anchor；错误候选一旦被标为 `binding`，
   会产生比普通噪声更强的锚定效应。
3. no-reasoning 模型的问题不是统一的“不会阅读长上下文”：部分题需要确定性日期
   算术，部分题需要 entity disambiguation，部分题只是 judge-compatible 的简洁表达。
   对所有 temporal 问题增加同一种计划会出现 gain/loss 抵消。
4. 局部 all-hit 子集的小幅提升无法外推到完整分布；这次全量配对验证及时暴露了
   route precision 不足。

## 下一步可通过验收的最小架构

下一版不应再复制 evidence 文本，而应让上游 QueryIR/关系代数直接向
`PreparedAnswer.trace` 传递类型化的 operand IDs、canonical timestamps 和来源证书：

1. 对 `DateDifference`、`Ordinal`、`LatestState` 分别建立高精度白名单执行器。
2. 只有两个 operands 均有唯一 source-backed binding、时间归一化成功且证书完整时，
   才执行确定性计算；不完整时保持 V5.54 prompt 字节级不变。
3. 给回答模型的辅助结构只包含紧凑的 `operand -> source turn -> normalized value` 表，
   不重复长 excerpt；可证明的数值题可直接 deterministic bypass。
4. 先在 untouched holdout 上要求每个 route 的 precision ≥99.5%、false-complete ≤0.5%，
   再运行双模型全量配对 no-regression 门禁。
