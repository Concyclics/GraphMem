## 1. 逐条判定

### 主张 A：「分层图索引让记忆联系起来，且不引入大量 token 开销」

**判定：不支持，且两个半句都被数据指向相反方向。**

| 子主张 | 实测 |
|---|---|
| 「分层」在起作用 | 427 张路由卡（level1=367 / level2=50 / level3=10）**从未作为检索入口**。`seeding.py` 的 `CHANNELS=("exact","bm25","dense")` 全是轮级通道，注释写明「Typed postings retrieve graph nodes, not turns」。`refines_to` 只是遍历里平权的一条边，且 `include_inverse=True` 使上行/下行不可区分。 |
| 「记忆联系起来」 | 原图 **21,117 条边全部落在单一 session 内**（按证据组回溯 session，8 种关系无一例外 0.0%）。`cross_session_merge` / `cross_session_portals` / `entity_merge` 三个开关全部关闭。 |
| 「不引入大量 token 开销」 | 构建成本 **126K–270K token/memory**（phase_a 六臂实测），LongMemEval 每题一个 memory、**无法跨题摊销**。既有报告已把「首次构建便宜」列为不被支持的主张。 |

**⚠️ 一处需要核对的数字冲突**：`V5_8_CROSS_SESSION_KEY.md` 报「124/21,117 条边（0.59%）离开其 session」，
本轮测得 **0 条**。两者口径可能不同（本轮按 `evidence_group → session` 回溯，
该文档可能按 `src/dst` 节点的 session 属性）。**报告引用任一数字前必须先统一口径。**

### 主张 B：「在两个 benchmark 上通过 gold 与非 gold 的稀有词重叠证明了这点」

**判定：部分支持，但只有一个 benchmark，且唯一的双语料测试是失败的。**

- 14–21x 分离度、gold 对落在前 5%（85–96%）——**只在 LongMemEval 上测**
  （324 题，`longmemeval_s_cleaned.json` 原文会话粒度）。
- **LoCoMo 从未做过同一测量**。`probe_join` 只测到 LoCoMo 在 df≤5% 下几乎没有连接边
  （12–21 对/memory，而 LME 约 250 对）。
- 唯一同时跑在两个语料上的实验（BM25 锚点 + 稀有词扩展）**在两个子集、三组阈值下全部输给平铺 top-k**。

**可写的表述**：「在 LongMemEval 上量化了跨会话指称信号」——不能写「在两个 benchmark 上证明」。

### 主张 C：「multi-hop 下命中一个 gold 后，有更大概率补齐其余 gold」

**判定：作为数据性质成立；作为已实现机制不成立。这是全篇最需要小心的一条。**

| 口径 | 数值 | 含义 |
|---|---:|---|
| **过滤器指标** | K≥3 时 gold 会话对召回 **92.3%**，候选对仅占全部的 12%（130 边/memory） | 信号真实存在 |
| **排序器指标** | 从 BM25 锚点出发取稀有词邻居 top-2：单会话题 83.5% vs 平铺 84.5%；多会话题 15.4% vs 平铺 16.7% | **全部输** |
| **端到端** | `shared_referent` 13,386 条边接入导航器后 **+0.13pp**（p≈1.0） | 无收益 |

原因：稀有词是**好过滤器、坏排序器**。锚点每个约有 10 个稀有词邻居，
取 top-2 时 IDF 加权分排不出 gold；而该分数**与问题无关**，
输给问题条件的词法分是系统性的，不是调参问题。

**可写的表述**：「我们量化了一个此前未被利用的跨会话指称信号（92.3% 召回 @ 12% 候选），
并报告了将其作为排序器的失败，指出它应作为过滤器使用」——这是诚实且有价值的贡献。
**不能写**「实现了 multi-hop 补齐」。

### 主张 D：「关系代数 + 图搜索排序保证证据完整性与预算内更充分的内容」

**判定：不支持，且被数据指向相反方向。**

- **关系代数在约 0 道题上触发**：`CLOSED_FORM_KINDS`/AST 消费 `canonical_fact`，
  而 `collection_key` 已退化为 5 个 value_type（text 3959 / number 398 / time 210 /
  currency 58 / boolean 44），`predicate` 92.1% 唯一——没有同类项可 group。
- **带完整 harness 的 h10 比 legacy h0 低 13pp**（0.5848 vs 0.7004，
  143胜45负，p=4.31e-13）；h8/h9（fact 蓄水池）比 h0 低 **28pp**。
- **「预算内更充分」与实测相反**：token 预算 5000 只用了 **25–29%**
  （h0 1254 / h10 1452），**0/300 题触及上限**；紧约束是轮次上限 32。
  平均每轮约 45 token，**在不超 token 的前提下可装约 110 轮**。
  也就是说当前设计**没有用满预算**，而不是「在预算内更充分」。
- 且 **h0 用更少的 token（少 14%）取得高 13pp 的检索命中**。

### 主张 E：「mem0 为省 token 用 append-only，破坏关系连接，不得不用 top-200 宽召回」

**判定：无法验证；既有报告已明确列为不可做的对比。**

`graphmem_mem0_comprehensive_report_20260804.md` 第 12/111/225 行：

> 「Mem0 附件只保存答案和 judge usage，没有暴露 memory ingestion、search、answer 的
> cached input、uncached input 和 output，因此目前**不能进行数值化的 GraphMem–Mem0
> memory-stage token 对比**。」
> 不被支持的主张包括：「GraphMem 比 Mem0 节省 X% token」。

- 「append-only 破坏关系连接」：本轮无任何 mem0 侧测量。
- 「top-200 宽召回」：本轮无任何 mem0 检索宽度测量。
- 该报告第 242 行已给出补测方案：为 mem0 的 `add/search/answer` 增加 token interceptor，
  在**相同模型、相同题目、相同缓存策略**下重跑，分别报告构建与查询的
  cached/uncached/output 与 P50/P95/max。

## 2. 目前站得住的贡献（重新表述）

以下五条全部有本轮配对实验支撑，可以直接写。

### C1. 跨会话指称信号的量化（LongMemEval，324 题）

| 类别 | gold 会话对共享稀有词 | 随机对 | 分离度 | gold 进前 5% |
|---|---:|---:|---:|---:|
| multi-session | 15.1 | 1.1 | 13.9x | 85.0% |
| temporal | 22.6 | 1.1 | 20.7x | 85.8% |
| knowledge-update | 20.4 | 1.1 | 19.0x | 96.2% |

K≥3 时 gold 会话对召回 92.3%，候选仅占全部会话对的 12%（130 边/memory，零 LLM 调用）。
**对照**：精确实体名 0.6% 召回；摘要 embedding 需 35% 的候选对才有 98.8%。

### C2. 系统性消融与七个否定结果（本报告的主体）

| 假设 | 依据 | 实测 |
|---|---|---|
| 跨会话边不足 | 原图 0 条跨会话边 | 加 13,386 条 → +0.13pp |
| harness 被饿死 | h8/h9 低于 legacy 28pp | 给边不动——是**撑死**非饿死 |
| 图候选挤占槽位 | 纯图占包 25.9%、gold 产出 0.4% | 衰减+剪枝 +1.31pp（p=0.064） |
| operand 无界项失衡 | 纯图 fused 2.41 vs 词法 1.24 | 封顶/去掉 ±0.26pp |
| `_rank_pack` 有缺陷 | 池 94.95% → 包 62.9% | oracle 证明**打包零损失** |
| 稀有词可做同层扩展 | 会话对 14–21x 分离 | 两子集三阈值全输平铺 |
| 会话路由可拿 +19.3pp | 单会话 oracle 1.0 vs 实际 0.6895 | **+1.58pp** |

### C3. Oracle 分解：瓶颈的精确定位

```
候选池 gold 覆盖 94.95%（结构上界 95.76%）
打包后 gold 保留 62.9%
all_hit 0.5848 → oracle 会话路由 0.9474（+36.3pp）
  单会话题 (78.7%)  实际 0.6895  oracle 1.0000
  多会话题 (21.3%)  实际 0.1975  oracle 0.7531
```
**且 oracle 的收益来源是「候选池比预算还小」**（1.35 会话 ≈ 31 轮 ≈ 32 预算，等于全取），
不是「选对会话」——路由 top-3 是 93 轮抢 32 槽位，超订 3 倍，排序问题原封不动。
这解释了为什么所有召回侧改动都只值 1pp 量级。

### C4. 图遍历的饱和性质

| hops/nodes | gold 覆盖 | 走边/题 |
|---|---:|---:|
| 2/96（当前） | 94.95% | 32.6 |
| 3/256 | 94.95%（**零增益**） | 192.2 |
| 4/512 | 95.67% | 358.6 |
| 6/2048 | 95.76% | 360.7 |

beam 16/32/off **逐位完全相同**；走边只用掉预算的 23%——**遍历是种子受限，非预算受限**。
当前预算已拿到结构上界的 **99.2%**。

### C5. 预算利用率

token 上限 5000 仅用 25–29%，0/300 题触及；紧约束是轮次上限 32，
平均每轮约 45 token，**可装约 110 轮**。证据预算 32→48→64 单调 +5.5pp，
即「每一步只是在收回本来就闲置的预算」。

### 已确认有收益的改动合计

证据预算 +5.5pp、会话路由 top-8 +1.58pp（p=0.050）、跳数衰减 +0.92pp、
exact 权重 1.2→1.0 +0.79pp（p=0.031）、逐步剪枝 +0.39pp。
**合计约 +9pp，叠加后 0.67–0.68，仍低于 h0 legacy 的 0.7004。**

## 4. 建议的报告结构

现有证据支撑的是一篇**实证研究**，而不是一篇方法论文。核心贡献是
「我们构建了分层图记忆系统并系统性测量了每个机制的真实贡献，多数没有贡献，
以及为什么」，加上「我们发现了一个尚未被利用的跨会话信号」。

1. **动机**：长对话记忆需要跨会话关联（可保留 mem0 的定性动机，
   但**在 #2 完成前不给 token 数字**）。
2. **系统**：分层图索引 + Query IR + 关系代数 + 证据打包。
   **如实说明**：分层在召回侧目前未被使用、关系代数因键退化而未触发。
3. **诊断方法**：oracle 分解、饱和性扫描、配对 McNemar（C3/C4）。
4. **发现一 · 跨会话指称信号**（C1）：包括它作为过滤器成立、作为排序器失败。
5. **发现二 · 七个否定结果**（C2）：这是最有价值的部分。
6. **发现三 · 预算与瓶颈**（C5 + C3）：候选池超订 3–18 倍是所有召回侧改动只值 1pp 的根因。
7. **局限**：LME n=1、单一图单一种子、仅 all_hit 无判分、无 mem0 数值对比。

**必须在方法节交代的口径问题**：
- 「gold 100% 在候选池」与「94.95%」是两个口径（前者含会话扇出带进的零分轮次），以 94.95% 为准。
- cat4 占 55% 且从不需要第二会话，跨会话工作只在 cat1 的 142 题（18.7%）上计分。
- 进程内首臂的延迟数不可用（预热假象；曾据此错报剪枝 −53%，反序复测证伪）。
- 运行间抖动约 1 题。
