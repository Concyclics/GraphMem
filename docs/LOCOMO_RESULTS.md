# GraphMem 5.81.1：LoCoMo 复现结果

## 冷建库、自适应与开支账本

新方案从全部 **10 个 memory / 5,882 条原始消息** 冷建库，得到 **13,659 个图节点、23,734 条边**；原文摘要与历史库一致。实际检索容量分布：32 条 492 题、64 条 997 题、80 条 51 题；evidence-token 预算分布：2,200 为 623 题、3,800 为 866 题、4,500 为 51 题。全部题目走 V5.81 Graph + Source-focus，未触发 Prompt 超限回退。

最终解码修复后，复用**本轮冷建库生成且逐题哈希一致**的 1,540 份 Prompt，清除复制库中的旧答案缓存，再统一生成、评分。建图和检索配置未改变；只改变了回答解码参数。因此接受路径由 `runs/locomo-product` 的 build / prepare 和 `runs/locomo-final` 的 answer / judge 组成，并非将旧答案拼成新成绩。默认复现命令可从冷建库连续执行全部阶段。

| 阶段 | 实际 API 次数 | 输入 Token | 输出 Token | 总 Token |
|---|---:|---:|---:|---:|
| 冷建库 chat | 135 | 497,341 | 367,733 | 865,074 |
| 冷建库 embedding | 332 | 438,176 | 0 | 438,176 |
| 查询 / 检索 embedding | 671 | 68,385 | 0 | 68,385 |
| 最终回答 | 1,531 | 8,783,336 | 42,999 | 8,826,335 |
| 最终评分 | 1,542 | 1,171,356 | 65,355 | 1,236,711 |

冷建库一次性成本 **1,303,250 Token**；含建库、检索与回答，不含评分的本次总量 **10,197,970 Token**；加入评分为 **11,434,681 Token**。embedding 与 chat 是不同模型的 Token，分列后求和只用于本轮工作量盘点，不等于统一价格或 GPU 时间。

回答有 9 次运行内缓存命中，故实际调用少于题数；上表不对缓存元数据重复计费。评分含 2 次仅修复 JSON 格式的重试，已计入开支。接受路径所有调用均返回 usage，无 API 失败；单题逻辑 Token 均值与实际调用账本是两个明确分开的口径。

历史对照复用旧图和冻结 Prompt，其原 embedding 为 **BAAI/bge-m3**，没有重新建库 / 检索；两组共享相同原文、回答模型、解码参数和评分模板。对照只能用于本次端到端输出质量与回答 Token 比较，不能把差异单独归因于某一个优化，也不能据此比较冷建库成本。

## 工程验证与已修复问题

- **586 项回归测试通过**，包括核心算法、持久化、租户隔离、幂等、失败恢复、服务 API、答案缓存与复现账本。
- 安装 `graphmem-5.81.1` wheel 后在源码目录外启动真实 HTTP 服务，实际调用 GPU0 模型：写入 / prepare / answer、SIGKILL 后恢复、幂等重试、在线备份及新目录恢复均通过。
- Docker Compose 配置检查通过；本机无 Docker daemon 权限，未执行容器镜像构建或启动验收。
- 初次建图与另一组推理并行时发生 16 次超时，已改为顺序运行并增加复现进程锁。该中止轮次保留在 `runs/locomo-product-initial-mixed-load`。
- 最初 512 Token 输出上限下，产品出现 1 题截断，对照 2 题截断；单独试验 `repetition_penalty=1.05` 仍有 1 题循环输出。最终统一频率惩罚和 2,000 Token 上限后，两组全量重跑均零截断；没有按题目 ID 或参考答案特判。
- 历史冻结 Prompt 的打包估计未完整计入附加视图；复现脚本现验证消息哈希、用本地 tokenizer 重计正文并保留原估计，实际成本始终以 API usage 为准。

调试轮次、探针和对照消耗**不包含在上面的单次接受路径成本中**。超时和取消请求可能已有未返回的服务端开销，因此整个调试过程的总 Token 无法精确核算；已有日志与失败次数完整保留，机器汇总列出各诊断轮次的已观测消耗。
