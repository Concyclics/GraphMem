4. 创新一：Hierarchical Navigable Memory World

HNMW 将长期对话构造成可复用、可逐层定位、可沿关系导航并最终回溯原文的持久化记忆世界。其目标不是存储更多副本，而是让每次查询只读取最小完备证据。

Hierarchical
卡片 → Frame → 原文

粗层只做定位，细层承载答案事实。

Navigable
Typed relation 横向补证

状态、时间、问答和指代按需扩展。

Reusable
一次构建，多题查询

LoCoMo构建在1,986题间共享。

状态更新案例
周一：“计划坐火车去上海” → 周三：“取消火车票” → 周三：“已预订周四航班”。
问题“现在准备如何去上海？”先定位旅行卡片，沿状态链保留 train planned→cancelled 和 flight booked，再展开两条原文核验。系统不重放完整 transcript，也不会把旧计划误当当前状态。
HNMW解决“在哪里找、如何少读、如何复用”；它不意味着首次构建零成本。

5. 创新二：Graph Harness Query IR

Query IR 将自然语言问题编译为可执行的证据契约，让 dense、BM25、倒排索引、图遍历和 operator 围绕同一组 required roles 工作。

查询需求Required roles允许的补证路径
当前状态旧值、新值、操作、时间、sourcestate transition → source
时间比较事件A/B、时间A/B、sourcesame event / temporal endpoint
数量与列表范围、成员、add/remove、sourcecollection member → source
双人对话提问者、回复者、回复内容dialogue pair / next turn
时间比较案例
问题：“活动 A 比活动 B 早多少天？” Required roles = 事件A + 时间A + 事件B + 时间B + source。
如果只命中A，系统只能沿 same_event / temporal_endpoint 补齐B；四项证书完整后才允许日期差 operator。最终LLM负责表达，但不得改写已认证日期差。
Query IR解决“要找齐什么、允许沿哪些边走、什么时候停止、如何证明证据足够”。

6. 结论、边界与复现

可公开结论

  • LongMemEval：GraphMem 89.00%，Mem0 70.20%，提升 18.80 pp。
  • LoCoMo Category 1–4：GraphMem 86.23%，Mem0 78.90%，提升 7.34 pp。
  • 回答平均：LongMemEval 7,031 token/题，LoCoMo 4,413 token/题。
  • LoCoMo 每 conversation 构建平均 132,350 token，可由1,986题复用。

必须保留的边界

  • LongMemEval 首次构建平均 254,505 token/题，并不便宜。
  • Mem0附件没有 memory ingestion/search/answer usage，不能声明具体Token节省百分比。
  • 18.80 pp 是完整系统差异，不能全部归因于 Query IR 单模块。
  • LoCoMo Category 2/3 仍是 GraphMem 短板。
两个创新的组合价值
HNMW 把海量历史压缩成可复用、可导航的小工作集，负责“少读”；Graph Harness Query IR 把问题变成证据角色契约，负责“读对”。组合目标不是召回更多节点，而是用最少 token 构造 source-complete 的最小完备证据子图。
